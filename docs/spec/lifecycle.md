# ライフサイクル

[仕様の目次](README.md)

Binette の土台が、ページ・アプリ・プロセス・画面をいつ作り、いつ止め、いつ捨てるかを書きます。アプリから見える知らせ（終わりの処理、隠れた・見えた、後始末）は、この土台の上に乗る話で、後の節にまとめます。

決定はすべて 2026-10-27 です。のぞみが決めたもの（下では「決定」）と、のぞみが Claude の提案どおりでよいとしたもの（同じく「決定」）を含みます。まだ決めていないものは「未決」、形だけの提案は「案」と書きます。今のコードとの差は、各節の「実装」に書きます。

## 4 つの段（決定）

「アプリ ＝ 画面 ＝ プロセス」とは決めつけません。今はそれぞれ 1 つずつですが、言葉と API は段ごとに分けます。

| 段 | 何か | 今の実体 |
| --- | --- | --- |
| ページ（ホスト） | Binette が動いているブラウザのページ | タブ、またはインストールした PWA の窓 |
| アプリ | インストールされた定義 | `AppStore` の中の `InstalledApp`（app.json・HTML・WASM） |
| プロセス | 動いている実体 | Worker 1 つ（Régie の `RegieApp`） |
| 画面 | アプリを描く枠 | Scene の `mountApp` の枠。Réplique の `document` はこの枠のもの |

## ページ

### モード（決定）

インストールしていない状態（ブラウザのタブ）は **ライブモード** です。LiveDisk のように試すためのもので、使うならインストールが前提です。

| | ライブモード | インストール済み |
| --- | --- | --- |
| 見分け方 | 右以外 | `display-mode` が `standalone`・`minimal-ui`・`fullscreen`・`window-controls-overlay` のどれか。iPhone では `navigator.standalone` |
| 保存先 | メモリだけ（`createMemoryAppStore`）。IndexedDB などには書かない。閉じたら全部消える | IndexedDB（`createIndexedDbAppStore`）。`navigator.storage.persist()` を頼む |
| 表示 | 右下に「ライブモード」の透かし。インストールを勧める表示 | 透かしなし |
| オフライン | 使わない | Service Worker でキャッシュし、通信が無くても起動できる |
| 通知など | 使わない | 使える |
| 「戻る」 | ブラウザの「戻る」を History API で Binette の「戻る」につなぐ | Binette の帯の「戻る」 |

- ライブで試した内容は、インストールのときに引き継がない。iPhone ではタブとホーム画面のアプリの保存場所が別で、どうせ引き継げないため、どの環境でも同じ動きにそろえる
- タブ（ライブ）は、インストール版のデータを読まない。Chromium ではタブとインストール版が同じ保存場所を見るが、ライブはメモリの保存先しか使わない。インストールしている人がタブを開くと空のライブになるので、「インストール済みならアプリから開いてください」と添える
- ライブでも外のアプリを試しに入れてよい。メモリの中だけで、閉じたら消える
- 透かし（案）: 殻が一番上に薄く出す。`pointer-events: none` で、下のアプリを押せるままにする。iPhone の角やホームバーに隠れないよう safe area を取る。アプリの枠の外なので、アプリからは消せない
- インストールを勧める表示の形は未決。Chromium は `beforeinstallprompt` でボタンからインストールの画面を出せる。iPhone の Safari と Firefox にはその仕組みが無いので、「共有 → ホーム画面に追加」などの手順を見せることになる

実装: まだ。今はいつも IndexedDB を使い、透かしもモードの見分けも無い。

### ページの状態（決定）

| ページで起きたこと | Binette の扱い |
| --- | --- |
| 隠れた（`visibilitychange` で hidden） | 前面の画面も隠れた扱いにする |
| 凍結された（`freeze`） | すべてのプロセスが一時停止と同じになる。Binette は何もしなくてよい |
| 戻ってきた（visible、`resume`） | 前面の画面を見える扱いに戻す |
| 閉じた（`pagehide`）、ブラウザが落ちた | 何も知らせずに全部終わる |

ページが閉じるときには、何も確実には届きません。なので次を決まりにします。

- **保存は終わりの知らせに頼らず、変えたときにする**
- Binette の中で閉じたときと、ページごと切られたときを分ける（下の「終わり方」）

実装: まだ。

### Service Worker（決定）

- OS（Binette）が 1 つだけ持つ。アプリには登録させない。Service Worker はそのサイトのすべての通信を横取りできるため
- 役目は、インストール済みでのオフラインのキャッシュ。将来は、プッシュ通知などで、ページが閉じていても短時間だけ起こされる
- ずっと動き続けることはできない（ブラウザが数十秒で止める）ので、画面なしで動き続ける処理には使えない
- 将来、アプリが「通知が来たらこの関数を呼んで」と頼み、その中でアプリの WASM を画面なしで短く動かす形はとれる（未決）

実装: まだ。

## プロセス（決定）

```
起動中 ──→ 動作中 ⇄ 一時停止 ──→ 終了
```

| 状態 | 意味 |
| --- | --- |
| 起動中 | Worker を作り、WASM を読み、トップレベルの初期化（`_start`）を走らせている |
| 動作中 | イベントが届くと、アプリの関数を 1 回呼ぶ |
| 一時停止 | Worker は残すが、イベントを届けない |
| 終了 | Worker を捨てた。状態は消える |

- アプリは AS で async が無く、呼ばれたときだけ動いてすぐ返る。呼び出しの合間は何も動いていないので、一時停止は「イベントを届けない」だけで安全にできる
- 終了のきっかけ: 残す数の上限を超えた、アプリの中の例外や Worker の落ち（[regie.md](regie.md)）、ページが閉じた
- 呼び出しが返ってこない（無限ループ）ときの時間切れは未決

実装: 起動中・動作中・終了はある。一時停止はまだ。

## 画面と移り方（決定）

画面の状態は、見えている・隠れている・閉じた、の 3 つです。スマホのように、見えている画面はいつも 1 つです。

| できごと | 扱い |
| --- | --- |
| アプリを開く | そのアプリのプロセスが残っていれば、その画面を見せてプロセスを動作中に戻すだけ。無ければ起動する（下の「起動の順番」） |
| 戻る・別のアプリを開く | 今の画面を隠し、プロセスを一時停止して残す |
| 残す数の上限を超えた | いちばん長く使っていないものから閉じる |
| アプリが落ちた | 終了し、ホームに戻ってエラーを出す（[regie.md](regie.md)） |

- 残す数は、ホームのほかに 3 つ。ホームは上限に数えず、いつも残す
- 隠した画面は DOM ごと残す。戻ったときに、前の状態のまますぐ出せる

実装: まだ。今は、戻る・別のアプリを開くと、画面を消してプロセスを終了する。ホームも開くたびに起動し直す。

### 起動の順番（決定）

1. トップレベルの初期化（`_start`）
2. HTML を枠に描く
3. `start()`（あれば）。最初の画面はここで作る
4. あとはイベントのたびに 1 回呼ぶ。画面の操作は、1 回の呼び出しの分をまとめて反映する

実装: この順番のとおり（[regie.md](regie.md)、[scene/mount.md](scene/mount.md)）。

## 終わり方（決定）

| 終わり方 | 扱い |
| --- | --- |
| Binette の中で閉じた（上限で閉じる、アプリを閉じる） | 普通に終わりの処理をする。アプリの終わりの処理を呼び、それが返ってから Worker を止める |
| ページごと切られた（タブを閉じた、ブラウザが落ちた、OS がページを捨てた） | 終わりの処理は走らない。次にそのアプリを起動するとき、起動の中で後始末をさせ、それが済んでから起動完了にする |

- 後始末は、それが要るアプリだけ。後始末を持たないアプリは、いつもどおりに起動する
- 印はアプリが自分で付け外しする（案）。書きかけなど後始末が要る間だけ「後始末が要る」を立て、済んだら下ろす。印が立ったまま切られたときだけ、次の起動の `start()` の前に後始末を呼ぶ。後始末の途中の例外は、ほかと同じくアプリの終了
- 印は保存先に置くので、意味があるのはインストール済みのときだけ。ライブモードでは何も残らない
- 後始末に要る情報は、アプリが途中で保存しておく。終わりの処理は片付けのためのもので、保存の唯一の機会にはしない
- 終わりの処理が返ってこないときは、時間で打ち切り、ページごと切られたときと同じ扱いにする。時間の長さは未決
- OS 自身も同じ決まりに従う。Binette の保存（アプリのインストールなど）が途中で切れていたら、ホームを出す前に直す

実装: まだ。保存の API と一緒に作る。

## アプリから見える知らせ（決定 ＋ 案）

形は DOM にそろえます（決定）。`document` API と同じ考えで、新しい名前を覚えなくて済むようにします。

| 知らせ | 形（案） | 届く保証 |
| --- | --- | --- |
| 隠れた・見えた | `document.addEventListener("visibilitychange", …)` と `document.hidden` | なし。保存には使わない |
| 終わりの処理 | `pagehide` に似せたイベント。名前は未決 | Binette の中で閉じたときだけ |
| 後始末 | `start()` の前に呼ばれる。形と名前は未決 | 印が立ったまま切られたときだけ |

実装: まだ。後始末と終わりの処理は保存の API と一緒に、隠れた・見えたは画面を残す仕組みと一緒に作る。

## 今はやらないこと

- 画面なしで動き続けるサービス。今のアプリはイベントが無いと動かず、タイマーも通信も無いため、出番がない
- 何段階もの重要度。見えている画面が 1 つなら、「前面」と「残している」で足りる
- 1 つのアプリが複数の画面を持つこと。`document` は画面ごとのものなので、あとで広げられる
- 開いていた画面やスクロール位置の復元
- 落ちたアプリの自動の再起動
