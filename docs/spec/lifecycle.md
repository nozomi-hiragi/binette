# ライフサイクル

[仕様の目次](README.md)

Binette が、ページ・アプリ・プロセス・画面をいつ作り、いつ止め、いつ捨てるかを書きます。

決定はすべて 2026-10-27 です。のぞみが決めたもの、またはのぞみが Claude の提案どおりでよいとしたものは「決定」、形だけの提案は「案」、まだ決めていないものは「未決」と書きます。案は[最後の一覧](#案の一覧)にもまとめます。今のコードとの差は[実装の状況](#実装の状況)にまとめます。

## 言葉

### 4 つの段（決定）

「アプリ ＝ 画面 ＝ プロセス」とは決めつけません。今はそれぞれ 1 つずつですが、言葉と API は段ごとに分けます。

| 段 | 何か | 今の実体 |
| --- | --- | --- |
| ページ | Binette が動いているブラウザのページ | タブ、またはインストールした PWA の窓 |
| アプリ | インストールされた定義 | `AppStore` の中の `InstalledApp`（app.json・HTML・WASM） |
| プロセス | 動いている実体 | Worker 1 つと、その状態（Régie の `Process`。[regie/process.md](regie/process.md)） |
| 画面 | アプリを描く枠 | Scene のアプリの置き場（[scene/mount.md](scene/mount.md)）。Réplique の `document` はこの枠のもの |

### ほかの言葉

| 言葉 | 意味 |
| --- | --- |
| インスタンス | 起動したアプリ 1 つ分。プロセスと画面の組 |
| 状態 | インスタンスの状態。Create・Start・Resume・Pause・Stop・Destroy の 6 つ（下の「アプリの状態」） |
| スタック | 残しているインスタンスの並び。数に上限がある |
| 前面のアプリ | いま見えている画面のアプリ。いつも 1 つ |
| 最後の状態 | アプリごとに OS が記録する、いちばん新しい状態。次の起動で渡す |
| デバッグメニュー | 設定アプリの中にある、時間や数を変える所（下の「デバッグメニュー」） |

## ページ

### モード（決定）

インストールしていない状態（ブラウザのタブ）は **ライブモード** です。LiveDisk のように試すためのもので、使うならインストールが前提です。

ライブモードでするのは、それ用の表示だけです。保存などは特別に扱わず、インストール済みと同じに動きます。インストールしないとできない操作で、どうしようもないときは、アラートなどで知らせます。ライブモードだけの特別な扱いは、どうしても必要な場合だけにします。

| | ライブモード | インストール済み |
| --- | --- | --- |
| 見分け方 | インストール済みでないとき | `display-mode` が `standalone`・`minimal-ui`・`window-controls-overlay` のどれか。iPhone では `navigator.standalone`（案） |
| 表示 | 右下に「ライブモード」の透かし。インストールを勧める表示 | 透かしなし |
| 保存 | 同じ（IndexedDB） | 同じ（IndexedDB） |
| インストールが要る操作 | アラートなどで「インストールが要る」と知らせる | そのまま動く |

- ライブで試した内容は、インストールのときに引き継がない。引き継げることも保証しない（決定）。OS は引き継ぐための処理をしない。Chromium のように保存場所が同じなら見えることもあるが、それはたまたまで、当てにしない
- `display-mode` はインストールの有無そのものではなく、表示のしかた。`fullscreen` は、ふつうのタブを全画面にしただけでも当てはまるので、見分けには使わない。Binette の Web アプリマニフェストの `display` は `standalone` にする（案）
- 見分けは Scene の `isInstalled(window)` が受け持つ。`navigator.standalone === true` か上の 3 つの `display-mode` ならインストール済み。`matchMedia` の `change` で切り替え、`appinstalled` を受け取ったときもインストール済みの表示にする。テストなどでは `ShellOptions.installed` で上書きでき、指定時は `matchMedia` を使わない。DOM と window は表示先の element から辿り、`matchMedia` が無い環境はライブモードにする（案・実装済み）
- 透かしは、殻が一番上に薄く出す。`pointer-events: none` で下のアプリを押せるままにし、iPhone の角やホームバーに隠れないよう safe area を取る。ホームバーより上の表示領域の右下、アプリの枠の外に置くので、アプリからは消せない。飾りとして `aria-hidden="true"` にし、モードはボタンの aria-label で伝える（案・実装済み）
- インストールを勧める表示の形は未決。最小の案として、ライブモードのときだけホームバーの右端に「インストール」を出す。Chromium の `beforeinstallprompt` は `preventDefault()` して保持し、ボタンで一度だけ `prompt()` を呼ぶ。受け取れない場合や失敗した場合は、OS の `<dialog>` に手順と「閉じる」を出す。iPhone などは「Safari の共有 → ホーム画面に追加」、ほかは「ブラウザのメニューから『アプリをインストール』または『ホーム画面に追加』」。`showModal` が無い DOM では `open` 属性で代用する。閉じたことは保存しない。インストール済みになればボタン・透かし・開いている手順を消す（案・実装済み）
- インストールが要る操作のアラートには、インストールの手順（上と同じもの）を添える。OS 用の `MountedShell.requireInstall(reason)` は、インストール済みなら何も出さず true、ライブモードなら理由と手順の枠を出して false を返す。理由は textContent で入れ、HTML として読まない。Réplique・Régie には渡さず、通知などで実際に使うのは今後の作業（案・仕組みは実装済み）
- ブラウザによる違い（知っておくこと）:
  - iPhone では、タブとホーム画面のアプリで保存場所が別。タブで試したものは、インストールしても見えない。Chromium では同じ保存場所なので、タブとインストール版で同じデータが見える
  - iPhone の Safari は、インストールしていないサイトの保存を、7 日使わないと消すことがある。`navigator.storage.persist()` も、インストールしていないと断られやすい
  - iPhone の通知（プッシュ）は、インストールしないと使えない。これが「インストールが要る操作」の主なもの

### ページの識別子（決定）

OS がページに読まれるたびに、そのページの識別子を作ります。同じアプリを 2 つのタブや窓（Chromium ではライブモードのタブとインストール版も同じデータを見る）で開いたときの扱いは、OS は決めず、アプリが自分でします。そのために、識別子を `onCreate` から渡します。

- 識別子は読まれるたびに新しく作り、保存しない。たとえば `crypto.randomUUID()`（案）
- 最後の状態の記録に、それを記録したページの識別子も付ける（案）。`onCreate` で「前の記録は別のページのもので、まだ Destroy になっていない」と分かれば、別のタブで動いているか、そのタブが切られたかのどちらか

### ページで起きること（決定）

状態の移り方は、基本は OS の中の話です。ページから来るのは、ページが隠れたときに、前面のアプリを Pause にすることだけです。

| ページで起きたこと | Binette の扱い |
| --- | --- |
| 隠れた（`visibilitychange` で hidden） | 前面のアプリを Pause にする |
| 凍結された（`freeze`） | Stop までの計時を止める。ページの中は全部止まる |
| 戻ってきた（visible、`resume`） | そのときのページを確かめ、見えているときだけ、前面のアプリを Resume に戻す。Stop になっていたら `onStart(Stop)` → `onResume` |
| 閉じた（`pagehide`）、ブラウザが落ちた | 何も検知できない。何も知らせずに全部終わる |

`resume` は凍結が解けた知らせで、前面に戻った知らせではありません。凍結が解けても隠れたままのことがあります。なので、どの知らせのときも、`document.visibilityState` で今のページを確かめてから移します。フォーカスが外れただけ（blur）では Pause にしません（決定 2026-10-27）。

ページが閉じるときには、何も確実には届きません。なので **保存は終わりの知らせに頼らず、変えたときにする** のを決まりにします。

### Service Worker（決定）

- OS（Binette）が 1 つだけ持つ。アプリには登録させない。Service Worker はそのサイトのすべての通信を横取りできるため
- 役目は、オフラインのキャッシュ。将来は、プッシュ通知などで、ページが閉じていても短時間だけ起こされる
- ずっと動き続けることはできない（ブラウザが数十秒で止める）ので、画面なしで動き続ける処理には使えない
- 将来、アプリが「通知が来たらこの関数を呼んで」と頼み、その中でアプリの WASM を画面なしで短く動かす形はとれる（未決）

今のキャッシュの形は案・実装済みです。

- ルートの OS が本番だけ `sw.js` を scope `./` で登録する。開発サーバーでは登録しない。アプリには登録の API を渡さない
- `manifest.webmanifest` は name・short_name が Binette、display が standalone、start_url・scope が `./`。背景色とテーマ色は index.html の白に合わせ、自作の B の SVG を使う。SW・マニフェスト・アイコンは Vite の publicDir から dist 直下へ写す。URL は相対指定でサブパスにも置ける
- `binette-v0.2.0-1` に版付きのキャッシュを作る。install で `./`・`./index.html`・マニフェスト・アイコンを入れて skipWaiting、activate で古い `binette-` のキャッシュだけを消して clients.claim する
- ページの読み込み（navigate）はネットを先に試し、成功時にキャッシュを更新する。通信や HTTP の失敗では同じ URL のキャッシュ、それが無ければ `./`・`./index.html` の順に返す
- 同じオリジンのほかの GET はキャッシュを先に返し、裏で取り直して置き換える（stale-while-revalidate）。未保存ならネットから取って保存する。成功した応答だけを保存し、別のオリジンと GET 以外には触らない。ハッシュ付き JS や `.binapp` は SW の制御下で取得したときに入るため、初回の登録直後はオンラインで再読み込みしてからオフラインで使う

## アプリの状態（決定）

インスタンスの状態は 6 つです。アプリは同じ名前のメソッド（`onCreate` など）で知らされます。

| 状態 | 意味 | プロセス |
| --- | --- | --- |
| Create | インスタンスを作った | Worker を作り、WASM を読み、`_start` を走らせた |
| Start | 画面が見え始める | 動いている |
| Resume | 前面にいて、操作を受ける | 動いている。イベントのたびに 1 回呼ぶ |
| Pause | 離れたな、を検知した | Worker は残すが、イベントを届けない |
| Stop | だいぶ離れた | 同じ |
| Destroy | インスタンスを捨てる | Worker を止めた。中の状態は消える |

### 移り方

| できごと | 呼ぶもの |
| --- | --- |
| 起動（インスタンスが無い） | `onCreate(最後の状態)` → `onStart(Create)` → `onResume` |
| 画面を離れた（戻る、別のアプリを開く、ページが隠れた） | その瞬間に `onPause` |
| Pause のまま、Stop までの時間が過ぎた | `onStop` |
| Pause の間に戻ってきた | `onResume` だけ |
| Stop のあとに戻ってきた | `onStart(Stop)` → `onResume` |
| スタックから外れた、閉じた、更新・削除 | まだ Stop でなければ先に `onStop`、そのあと `onDestroy(理由)`。返ったら Worker を止める |
| 落ちた（例外、Worker の落ち、時間切れ） | 何も呼ばない（下の「落ちたとき」） |
| ページごと切られた | 何も呼ばない |

- Pause からすぐ Destroy にはならない。Destroy の前には必ず Stop を通る
- Stop からの Destroy は、いつでもあり得る。なのでアプリは、戻すのに要るものを Stop までに保存しておく。ページが隠れたまま切られると、ブラウザがタイマーを遅らせ、凍結・破棄するため、`onStop` まで届かないことが多い。保存は `onPause` までに済ませるのがおすすめ
- 前面のアプリは、基本 Destroy しない。Stop になっていても、スタックや OS の片付けでは消さない。消すのは、ユーザーが閉じたときと、更新・削除のときだけ
- 別のタブや背面で Pause になったときも、時間が過ぎれば Stop にする
- `onStart` には、Create のすぐあとか、Stop から戻ったのかを渡す
- 起動のときに `onCreate` → `onStart` → `onResume` を続けて呼ぶ、という順は案
- Stop までの時間は、ページが凍結されていた間を除いて数える。凍結が解けたら、残りの時間から数え直す（案）。凍結の間はブラウザがタイマーを動かさないので、OS は `freeze` と `resume` の時刻を覚えて差し引く
- アプリは AS で async が無く、呼ばれたときだけ動いてすぐ返る。呼び出しの合間は何も動いていないので、Pause と Stop は「イベントを届けない」だけで安全にできる

### 時間（決定）

| 時間 | 既定 | 過ぎたら |
| --- | --- | --- |
| Stop までの時間 | 10 秒 | Pause のアプリを Stop にする |
| 呼び出しの時間切れ | 5 秒 | 返ってこない（無限ループなど）。Worker ごと捨て、落ちたのと同じ扱い |
| `onDestroy` の時間切れ | 5 秒 | 打ち切って Worker を止める。ページごと切られたのと同じ扱い（最後の状態は Destroy の始まりのまま） |

Stop までの時間はデバッグメニューで変えられます（決定）。2 つの時間切れも変えられるようにします（案）。

## スタック（決定）

| できごと | 扱い |
| --- | --- |
| アプリを開く | インスタンスが残っていれば、その画面を見せる。Pause なら `onResume`、Stop なら `onStart(Stop)` → `onResume`。無ければ起動する |
| 戻る・別のアプリを開く | 今の画面を隠して Pause にし、インスタンスを残す |
| スタックの数を超えて起動した | いちばん古いインスタンスを Destroy する（理由 `System`・`Stack`） |

- スタックできるアプリの数は、デバッグメニューで決める。既定は 3。4 つ目のアプリが起動したら、いちばん古いアプリのインスタンスを Destroy する
- 見えている画面はいつも 1 つ。隠した画面は DOM ごと残し、戻ったときに前の状態のまますぐ出す
- ホームも、ほかのアプリと同じに数える。Destroy されていたら、ホームへ戻る操作でホームを普通に起動する
- 「いちばん古い」は、いちばん長く前面に出ていないもの（案）
- 数は 1 以上（案）

## ホームバー（案・実装済み）

OS が画面の下に、ホームへ戻るボタンと、残しているホーム以外のアプリの一覧を出します。名前のボタンで前面を切り替え、各アプリの「×」で閉じます。「×」は Pause → Stop → Destroy（User・Os）を通り、前面を閉じたらホームへ戻ります。ホームがスタックに無ければ起動します。ホームを表示している間もバーを出します。バーは上に区切りの線を持つ薄い帯で、どの画面でも同じ見た目にします（ホームの背景と同じ色でも見分けられるように）。

見た目は `:where(.bina-shell-…)` と `--bina-shell-…` で変更できます。各ボタンに「設定を開く」「設定を閉じる」などの aria-label を付け、前面のアプリの名前には aria-pressed を付けます。操作と見た目は、のぞみが画面を見て決めるための最小の案です。History API の戻るはまだ扱いません。

## 起動

### 順番（決定）

1. トップレベルの初期化（`_start`）。ここでアプリが `launch` で OS にインスタンスを渡す
2. HTML を枠に描く
3. `onCreate(最後の状態)` → `onStart(Create)` → `onResume`。最初の画面は `onCreate` で作る
4. あとはイベントのたびに 1 回呼ぶ。画面の操作は、1 回の呼び出しの分をまとめて反映する

### 起動の履歴（決定）

アプリの起動の履歴を、日時と識別子で、ログファイルのようにずっと取り続けます。最大の行数を設定で決め、既定は 100 行です。

- 1 件は `{ 日時, アプリの識別子 }`（案）
- 「起動」は、インスタンスを作ったとき（`onCreate` を呼ぶとき）。残っているものを前面に出すだけのときは数えない（案）
- 最大を超えたら、古い行から消す（案）

### ホームの選び方（決定）

Android の既定のホームアプリと同じ形にします。

- アプリは、`app.json` の `"role": "home"` で「ホームになれる」と手を挙げるだけ
- どのアプリをホームにするかは、OS の設定のオブジェクトの `home`（`installedAppKey(source, manifest.id)`）に記録する。OS は起動のときにこれを読んで、立ち上げるアプリを知る
- `home` が空のとき、またはそのアプリが無いときは、`role: "home"` のシステムアプリを使う（案）。選んでいたホームを削除したら、`home` を空に戻す（案）
- `home` を変えられるのは入手元が `binette:system` で `role: "settings"` の設定アプリだけ。保存済みの `role: "home"` のアプリの中から、入手元を問わず選ぶ（案・実装済み）
- 選んだらその場で保存し、以後のホームバー・前面を閉じたとき・finish・異常終了からの復帰は新しいホームを使う。前のホームのインスタンスは Stop → Destroy（User・Os）で捨てる。設定アプリは開いたままにする（案・実装済み）
- ホームだけが使う `apps.*` は選んだホームに渡す。ほかのホーム候補をアプリの一覧には並べない（案・実装済み）
- OS の設定のオブジェクトには、デバッグメニューの値も入れる（案・実装済み）。保存の API は [SystemStore](regie/store.md#systemstore案実装済み)

## 終わり方（決定）

| 終わり方 | 扱い |
| --- | --- |
| Binette の中で Destroy した（スタックから外れた、ユーザーが閉じた、アプリが自分を閉じた、更新・削除） | `onDestroy(理由)` を呼び、返ってから Worker を止める |
| 落ちた（例外、Worker の落ち、時間切れ） | 何も呼ばない。下の「落ちたとき」 |
| ページごと切られた（タブを閉じた、ブラウザが落ちた、OS がページを捨てた） | 何も呼ばない |

`onDestroy` は片付けのためのもので、保存の唯一の機会にはしません。

OS 自身も同じ決まりに従います。Binette の保存（アプリのインストールなど）が途中で切れていたら、ホームを出す前に直します。

### 最後の状態（決定）

- アプリごとに最後の状態を記録し、次の起動の `onCreate` に渡す。データの修復などは、アプリが自分でする
- 状態は、メソッドの始まりと終わりの両方で記録する。最後の記録が始まりのままなら、そのメソッドの途中で切られた・落ちたと分かる
- 最後の状態が Destroy の終わりでなければ、前回はきちんと閉じられなかったと分かる。修復の要らないアプリは、何もしなくてよい
- 初めての起動は「記録なし」（案）
- ページの識別子と、Destroy の理由も一緒に記録する（案）

### Destroy の理由（決定）

`onDestroy` に理由を渡します。理由は 2 段です。`User` なら、次は最初から始めてよい。`System` なら、元の画面に戻したい、とアプリが判断できます。

| 1 段目 | 2 段目（案） | いつ |
| --- | --- | --- |
| `User` | `Os` | OS の機能でユーザーが閉じた |
| `User` | `App` | アプリの中の機能でユーザーが閉じた（アプリが自分を閉じた） |
| `System` | `Stack` | スタックから外れた |
| `System` | `Update` | アプリを更新した |
| `System` | `Uninstall` | アプリを削除した |

メモリが足りないときに OS が片付ける、などは、あとで `System` に足します。

## 落ちたとき（決定）

アプリの中で例外が出た、Worker が落ちた、呼び出しが時間切れになった、のどれかを「落ちた」と呼びます。落ちたインスタンスは、何も呼ばずに捨てます（[regie/system.md](regie/system.md#落ちたとき)）。

- ホーム以外のアプリが落ちたら、ホームに戻ってエラーを出す
- ホームが落ちたら、ホームを起動し直す
- ホームが落ちては起動し直すのを繰り返し、5 秒たってもまた起動し直そうとしたら、代わりに **Apps** を出す（5 秒は案。デバッグメニューで変えられる、も案）
- Apps でホームへ戻る操作をしたら、ホームをもう一度起動する。また落ち続ければ、同じ決まりでまた Apps が出る

落ちたときのエラーは、状態表示（role=status）と onError に出します。最初の落ちから homeRetryWindow（既定 5 秒）を数え、起動失敗でも起動後の落ちでも同じように Apps へ切り替えます。起動を済ませてから homeRetryWindow 以上動いていたホームが落ちたら、落ち続けてはいないので数え直します。起動失敗では数え直しません（案・実装済み）。

ホームを起動し直す前には待ちます。最初は 100ms で、落ちるたびに倍にし、1000ms で頭打ちにします（100 → 200 → 400 → 800 → 1000ms）。起動してすぐ落ちるホームでも、5 秒の窓のあいだに数回しか起動し直しません。数え直すとき（起動を済ませたホームが homeRetryWindow 以上動いてから落ちた、ホームバーの「ホーム」で数え直した、ホームを選び直した）は 100ms に戻します。起動の途中で落ちたときも、動いている途中で落ちたときも同じです。待っているあいだに stop や別の移動があれば、起動し直しません（案・実装済み）。

### Apps（決定）

本当に最後の受け皿として、Binette に組み込みのアプリ **Apps** を置きます。

- インストールしてあるアプリの名前を、文字コード順に、縦に並べたリンクだけのアプリ
- 押したら、そのアプリを起動する。ほかには何もしない。見た目の飾りもしない
- 出てくるのは、上の「ホームが落ち続けたとき」だけ
- ホームや設定アプリなど、ほかのアプリの仕組みが壊れていても出せるよう、WASM のアプリではなく OS が直接描く（案）。なので Apps 自身は落ちず、スタックにも数えない（案）

今の形は案・実装済みです。

- 並べるのはホームに渡す一覧と同じアプリ。role home の候補を除き、設定アプリは含む。名前を UTF-16 コード単位の辞書順（`<`・`>`）で比べる
- 見出しや飾りは付けず、縦に並べたリンクの見た目の `<button type="button">` だけにする。名前は textContent で入れ、「設定を開く」などの aria-label を付ける
- アプリの枠とは別の要素を枠と同じ並びに置き、`:where(.bina-shell-apps…)` と `--bina-shell-…` で見た目を決める。Apps はホームバーの一覧にも出さない
- Apps からアプリを開いたら Apps を隠す。開いたアプリを閉じた・finish した・落ちたときは、ホームが動いていなければ Apps に戻る
- ホームバーの「ホーム」は、Apps がアプリの背面にあるときも、最初の落ちの時刻を消してホームを再試行する。起動できれば以後は普通にホームへ戻り、また落ち続ければ Apps を出す
- 設定でホームを選び直したときも失敗の計時を消し、以後は選んだホームへ戻る。システムの stop は Apps も消す

## アプリから見える形

ひとまず `App` クラスをアプリの大本に置きます（決定）。メソッドは `onCreate`・`onStart`・`onResume`・`onPause`・`onStop`・`onDestroy` の 6 つです（決定）。アプリが自分を閉じることもできます（決定）。ホームと設定も `App` で書きます（決定）。

```ts
import { App, Last, State, DestroyKind, DestroyReason, document, launch } from "jsr:@binette/replique";

class Memo extends App {
  onCreate(last: Last): void {
    if (!last.done) {
      // last.state のメソッドの途中で切られた・落ちた。ここで直す
    } else if (last.state != State.None && last.state != State.Destroy) {
      // Destroy まで来ずに終わった
      if (last.page != this.page) { /* 別のタブで動いている、またはそのタブが切られた */ }
    } else if (last.state == State.Destroy && last.reason.kind == DestroyKind.System) {
      // OS が Destroy した。元の画面に戻す
    }
    document.getElementById("save").addEventListener("click", () => {
      memo.save();   // () => {} の中では this もローカル変数も使えないので、グローバルを通す
    });
  }

  onStart(last: State): void {
    if (last == State.Stop) { /* しばらく離れていた。表示を新しくするなど */ }
  }

  onPause(): void { /* ここまでに保存しておく */ }

  onDestroy(reason: DestroyReason): void { }

  save(): void { }
}

const memo = new Memo();
launch(memo);
```

案の形:

| 名前 | 中身 |
| --- | --- |
| `App` | Réplique の基底クラス。6 つのメソッドはどれも中身が空で、要るものだけ上書きする |
| `launch(app)` | トップレベルで 1 回呼び、OS にインスタンスを渡す（名前はのぞみの提案。Flutter の `runApp` と同じ役目） |
| `this.finish()` | アプリが自分を閉じる。Pause → Stop → Destroy（`User`・`App`）の順に通り、前の画面に戻る |
| `this.page` | 今のページの識別子 |
| `State` | `None`（記録なし）・`Create`・`Start`・`Resume`・`Pause`・`Stop`・`Destroy` |
| `Last` | 最後の記録。`state`（`State`）・`done`（そのメソッドが終わったか）・`page`（記録したページの識別子）・`reason`（Destroy の理由） |
| `DestroyReason` | `kind`（`DestroyKind.User`・`System`）と `cause`（`Os`・`App`・`Stack`・`Update`・`Uninstall`） |

- `onStart` に渡すのは `State.Create` か `State.Stop`
- メソッドの中の例外は、ほかと同じく「落ちた」
- AS では `() => {}` の中で `this` もローカル変数も使えない。ハンドラーからは、グローバルに置いたインスタンス（上の `memo`）を通す

## デバッグメニュー（決定）

設定アプリの中に置きます。

| 項目 | 既定 | |
| --- | --- | --- |
| スタックできるアプリの数 | 3 | 決定 |
| Stop までの時間 | 10 秒 | 決定 |
| 起動の履歴の最大の行数 | 100 行 | 決定 |
| 呼び出しの時間切れ | 5 秒 | 時間は決定、変えられるのは案 |
| `onDestroy` の時間切れ | 5 秒 | 時間は決定、変えられるのは案 |
| Apps を出すまでの時間 | 5 秒 | 案 |

決めた値は保存します（案・実装済み）。設定アプリの `os.*` で読み書きします。画面は「名前 値 − ＋」の行で、数は 1（履歴は 10）ずつ、時間は 1 秒ずつ変えます。スタックは 1 以上、履歴は 0 以上、Stop と Apps の時間は 0 以上、2 つの時間切れは 1 秒以上です。下限で − を押しても変わりません。起動の履歴は新しい順に UTC の `YYYY-MM-DD HH:MM:SS アプリの名前` を並べます。名前が見つからなければ識別子を使います。履歴は設定アプリのインスタンスを作る直前の写しで、閉じて開き直すと新しくなります（案・実装済み）。

### 値を変えたときに効く所（案・実装済み）

その場でシステム（[regie/system.md](regie/system.md#os-の設定案)）の設定を変え、SystemStore に保存します。

| 値 | いつから使うか |
| --- | --- |
| stackSize | 次にインスタンスを作るときに片付ける。減らしたその場では閉じず、残っている画面を前面に出すだけでも片付けない |
| stopDelay | 今あるインスタンスも含め、次に Pause になるとき。今の Pause の計時は変えない |
| callTimeout・destroyTimeout | 次にインスタンスを作るとき |
| historyLimit | 次に起動の履歴を足すとき。減らしたその場では消さない |
| homeRetryWindow | 次にホームが落ちたとき |

## 実装の状況

App と 6 つの状態、ページの識別子、非表示・凍結・再開、時間切れ、スタック、最後の状態、起動の履歴、OS の設定の保存、Apps、ライブモードの表示とインストール案内、Service Worker を実装しています。ホームバー・Apps・ライブモードの見た目と操作、キャッシュの形は案です。

| 項目 | 今 |
| --- | --- |
| モードの見分け、透かし、インストールが要る操作のアラート | isInstalled と installed の上書き、display-mode の change、appinstalled、透かし、ホームバーのインストールボタン、prompt と手順の dialog、requireInstall を実装。保存はいつも IndexedDB で、これは決まりどおり。インストールを必須とする操作自体はまだ無い |
| ページの識別子、ページで起きること | startSystem ごとに UUID を作り、this.page で渡す。hidden で Pause、visible で Resume。blur だけでは移さず、freeze の間は Stop の時間を数えない |
| Service Worker | 本番の OS だけが登録。マニフェストと自作アイコンを同梱。版付きキャッシュ、navigate はネット優先、同じオリジンのほかの GET は stale-while-revalidate。開発では登録しない。プッシュ通知は未実装 |
| アプリの状態 | `_start` → HTML → Create → Start(Create) → Resume。Pause・Stop の間はイベントを届けない。起動の途中のクリックは Resume のあとに届ける（[scene/mount.md](scene/mount.md)） |
| 時間切れ | 呼び出しと _start は既定 5 秒で終了。onDestroy は既定 5 秒で打ち切り、エラーを出さない。Pause から既定 10 秒で Stop |
| スタック | 既定 3（ホームを含む）。画面を隠して Pause にし、DOM と Worker を残す。残っていれば Resume、Stop なら Start(Stop) → Resume。上限を超えたら、前面以外で最も長く前面に出ていないものを Stop → Destroy（System・Stack） |
| 起動の履歴、最後の状態 | SystemStore に保存。各メソッドの前後に state・done・page・reason を書き、次の Create に渡す。初回は None・done=true。起動のたびに日時と installedAppKey を記録し、既定 100 件を残す。前面に出すだけでは記録しない |
| Destroy の理由、自分を閉じる | 実装済み。finish は今の呼び出しのあと Pause → Stop → Destroy（User・App）でホームに戻る。ホーム自身なら起動し直す |
| 落ちたとき | 状態を知らせずに捨て、前面ならホームに戻ってエラーを出す。隠れたアプリなら前面を変えずにエラーを出す。ホームの終了や起動失敗はホームを起動し直す。最初の落ちから 5 秒（`homeRetryWindow`）を過ぎても落ち続けたら Apps を出す |
| Apps | OS が DOM を直接描く。ホームの一覧と同じアプリ（ホーム候補以外、設定を含む）の名前を文字コード順に縦に並べる。スタックやホームバーの一覧には入れない。開いたアプリを閉じたら Apps に戻り、ホームバーの「ホーム」で計時を消してホームを再試行する |
| `App` クラス | launch で一回だけ渡し、6 つのメソッドを上書きできる。二回の launch はアプリの終了 |
| デバッグメニュー | 設定アプリの − ＋ と os.* を実装。値は SystemStore に保存し、上の表の時点から使う。システムの作り直しでも残り、SystemOptions より優先する |
| ホームの選び方 | installedAppKey を home に保存。保存済みの role home を入手元に関係なく選べる。空・見つからない場合は system のホーム。変更後は新しいホームに apps.* を渡し、前のホームは User・Os で Destroy。アプリの削除が無いので、削除時に home を空にする処理はまだ無い（[regie/system.md](regie/system.md)） |

## 今はやらないこと

- 画面なしで動き続けるサービス。今のアプリはイベントが無いと動かず、タイマーも通信も無いため、出番がない
- 何段階もの重要度。見えている画面が 1 つなら、「前面」と「残している」で足りる
- 1 つのアプリが複数の画面を持つこと。`document` は画面ごとのものなので、あとで広げられる
- 開いていた画面やスクロール位置を OS が戻すこと（アプリが最後の状態を見て自分でする）
- ホーム以外の落ちたアプリを、自動で起動し直すこと

ページ
