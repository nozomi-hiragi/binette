# ライフサイクル

[仕様の目次](README.md)

Binette の土台が、ページ・アプリ・プロセス・画面をいつ作り、いつ止め、いつ捨てるかを書きます。アプリから見える形（`App` クラスと、その 6 つのメソッド）は、後の節にまとめます。

決定はすべて 2026-10-27 です。のぞみが決めたもの（下では「決定」）と、のぞみが Claude の提案どおりでよいとしたもの（同じく「決定」）を含みます。まだ決めていないものは「未決」、形だけの提案は「案」と書きます。今のコードとの差は、各節の「実装」に書きます。

## 4 つの段（決定）

「アプリ ＝ 画面 ＝ プロセス」とは決めつけません。今はそれぞれ 1 つずつですが、言葉と API は段ごとに分けます。

| 段 | 何か | 今の実体 |
| --- | --- | --- |
| ページ（ホスト） | Binette が動いているブラウザのページ | タブ、またはインストールした PWA の窓 |
| アプリ | インストールされた定義 | `AppStore` の中の `InstalledApp`（app.json・HTML・WASM） |
| プロセス | 動いている実体 | Worker 1 つ（Régie の `RegieApp`） |
| 画面 | アプリを描く枠 | Scene の `mountApp` の枠。Réplique の `document` はこの枠のもの |

## ページ

### モード（決定）

インストールしていない状態（ブラウザのタブ）は **ライブモード** です。LiveDisk のように試すためのもので、使うならインストールが前提です。

| | ライブモード | インストール済み |
| --- | --- | --- |
| 見分け方 | 右以外 | `display-mode` が `standalone`・`minimal-ui`・`fullscreen`・`window-controls-overlay` のどれか。iPhone では `navigator.standalone` |
| 保存先 | メモリだけ（`createMemoryAppStore`）。IndexedDB などには書かない。閉じたら全部消える | IndexedDB（`createIndexedDbAppStore`）。`navigator.storage.persist()` を頼む |
| 表示 | 右下に「ライブモード」の透かし。インストールを勧める表示 | 透かしなし |
| オフライン | 使わない | Service Worker でキャッシュし、通信が無くても起動できる |
| 通知など | 使わない | 使える |
| 「戻る」 | ブラウザの「戻る」を History API で Binette の「戻る」につなぐ | Binette の帯の「戻る」 |

- ライブで試した内容は、インストールのときに引き継がない。iPhone ではタブとホーム画面のアプリの保存場所が別で、どうせ引き継げないため、どの環境でも同じ動きにそろえる
- タブ（ライブ）は、インストール版のデータを読まない。Chromium ではタブとインストール版が同じ保存場所を見るが、ライブはメモリの保存先しか使わない。インストールしている人がタブを開くと空のライブになるので、「インストール済みならアプリから開いてください」と添える
- ライブでも外のアプリを試しに入れてよい。メモリの中だけで、閉じたら消える
- 透かし（案）: 殻が一番上に薄く出す。`pointer-events: none` で、下のアプリを押せるままにする。iPhone の角やホームバーに隠れないよう safe area を取る。アプリの枠の外なので、アプリからは消せない
- インストールを勧める表示の形は未決。Chromium は `beforeinstallprompt` でボタンからインストールの画面を出せる。iPhone の Safari と Firefox にはその仕組みが無いので、「共有 → ホーム画面に追加」などの手順を見せることになる

実装: まだ。今はいつも IndexedDB を使い、透かしもモードの見分けも無い。

### ページの状態（決定）

| ページで起きたこと | Binette の扱い |
| --- | --- |
| 隠れた（`visibilitychange` で hidden） | 前面の画面も隠れた扱いにする（アプリには `onPause`） |
| 凍結された（`freeze`） | すべてのプロセスが一時停止と同じになる。Binette は何もしなくてよい |
| 戻ってきた（visible、`resume`） | 前面の画面を見える扱いに戻す（アプリには `onResume`、Stop のあとなら `onStart` → `onResume`） |
| 閉じた（`pagehide`）、ブラウザが落ちた | 何も知らせずに全部終わる |

ページが閉じるときには、何も確実には届きません。なので次を決まりにします。

- **保存は終わりの知らせに頼らず、変えたときにする**
- Binette の中で閉じたときと、ページごと切られたときを分ける（下の「終わり方」）

実装: まだ。

### Service Worker（決定）

- OS（Binette）が 1 つだけ持つ。アプリには登録させない。Service Worker はそのサイトのすべての通信を横取りできるため
- 役目は、インストール済みでのオフラインのキャッシュ。将来は、プッシュ通知などで、ページが閉じていても短時間だけ起こされる
- ずっと動き続けることはできない（ブラウザが数十秒で止める）ので、画面なしで動き続ける処理には使えない
- 将来、アプリが「通知が来たらこの関数を呼んで」と頼み、その中でアプリの WASM を画面なしで短く動かす形はとれる（未決）

実装: まだ。

## プロセス（決定）

```
起動中 ──→ 動作中 ⇄ 一時停止 ──→ 終了
```

| 状態 | 意味 |
| --- | --- |
| 起動中 | Worker を作り、WASM を読み、トップレベルの初期化（`_start`）を走らせている |
| 動作中 | イベントが届くと、アプリの関数を 1 回呼ぶ |
| 一時停止 | Worker は残すが、イベントを届けない |
| 終了 | Worker を捨てた。状態は消える |

- アプリは AS で async が無く、呼ばれたときだけ動いてすぐ返る。呼び出しの合間は何も動いていないので、一時停止は「イベントを届けない」だけで安全にできる
- 終了のきっかけ: 残す数を超えて解放した、アプリの中の例外や Worker の落ち（[regie.md](regie.md)）、ページが閉じた
- 呼び出しが返ってこない（無限ループ）ときの時間切れは未決

実装: 起動中・動作中・終了はある。一時停止はまだ。

## 画面と移り方（決定）

画面の状態は、見えている・隠れている・閉じた、の 3 つです。スマホのように、見えている画面はいつも 1 つです。

| できごと | 扱い |
| --- | --- |
| アプリを開く | そのアプリのインスタンスが残っていれば、その画面を見せてプロセスを動作中に戻すだけ。無ければ起動する（下の「起動の順番」） |
| 戻る・別のアプリを開く | 今の画面を隠し、プロセスを一時停止して残す |
| 残す数を超えて起動した | いちばん古いアプリのインスタンスを解放する |
| アプリが落ちた | 終了し、ホームに戻ってエラーを出す（[regie.md](regie.md)） |

- 残す（スタックできる）アプリの数は、デバッグメニューで決められる。既定は 3。4 つ目のアプリが起動したら、いちばん古いアプリのインスタンスを解放する（決定）
- ホームは数に入れず、いつも残す（案）。「いちばん古い」は、いちばん長く前面に出ていないもの（案）。値は 1 以上で、インストール済みでは保存する（案）。デバッグメニューの置き場所は未決
- 隠した画面は DOM ごと残す。戻ったときに、前の状態のまますぐ出せる

実装: まだ。今は、戻る・別のアプリを開くと、画面を消してプロセスを終了する。ホームも開くたびに起動し直す。

### 起動の順番

1. トップレベルの初期化（`_start`）。ここでアプリが `register` する（案）
2. HTML を枠に描く
3. `onCreate(最後の状態)` → `onStart` → `onResume`（決定は 6 つのメソッドがあること。この順に続けて呼ぶのは案）。最初の画面は `onCreate` で作る
4. あとはイベントのたびに 1 回呼ぶ。画面の操作は、1 回の呼び出しの分をまとめて反映する

実装: 今は 1・2・4 と、3 の代わりの `start()`（[regie.md](regie.md)、[scene/mount.md](scene/mount.md)）。

### 起動の履歴（決定）

アプリの起動の履歴を、日時と識別子でログのように取り続けます。

- 1 件 = `{ 日時, アプリの識別子 }`（案）
- 「起動」は、インスタンスを作ったとき（`onCreate` を呼ぶとき）。残っているものを前に出すときは数えない（案）
- インストール済みは IndexedDB、ライブモードはメモリ（案）
- 何件まで残すか、どこで見るかは未決

実装: まだ。

## 終わり方（決定）

| 終わり方 | 扱い |
| --- | --- |
| Binette の中で解放した（スタックから外れた、故意に破棄した） | 普通に終わりの処理をする。アプリの `onDestroy` を呼び、それが返ってから Worker を止める |
| アプリの中の例外・Worker の落ち | 何も呼ばない。アプリを終了し、ホームに戻ってエラーを出す（[regie.md](regie.md)） |
| ページごと切られた（タブを閉じた、ブラウザが落ちた、OS がページを捨てた） | 何も呼ばない |

- アプリごとに最後の状態（create・start・resume・pause・stop・destroy）を記録する。次の起動の `onCreate` でその最後の状態を受け取り、データの修復などはアプリが自分でする（決定）
- 最後の状態が destroy でなければ、前回はきちんと閉じられなかったと分かる。修復が要らないアプリは、何もしなくてよい
- 記録するのは、アプリのメソッドが返ったあと。途中で例外が出たら記録しない。初めての起動は「記録なし」（案）
- 記録は保存先に置く。インストール済みは IndexedDB、ライブモードはメモリだけで、ページを開き直すと「記録なし」になる（案）
- 修復に要る情報は、アプリが途中で保存しておく。`onDestroy` は片付けのためのもので、保存の唯一の機会にはしない。ページが隠れたまま切られると `onStop` まで届かないことが多い（ブラウザが隠れたページのタイマーを遅らせ、凍結・破棄するため）ので、保存は `onPause` までに済ませるのがおすすめ。ただし届く保証はない
- `onDestroy` が返ってこないときは、時間で打ち切り、ページごと切られたときと同じ扱いにする。時間の長さは未決
- OS 自身も同じ決まりに従う。Binette の保存（アプリのインストールなど）が途中で切れていたら、ホームを出す前に直す

実装: まだ。

## アプリから見える形

ひとまず `App` クラスをアプリの大本に置きます（決定）。メソッドは `onCreate`・`onStart`・`onResume`・`onPause`・`onStop`・`onDestroy` の 6 つです（決定）。

```ts
import { App, State, register } from "jsr:@binette/replique";

class Memo extends App {
  onCreate(last: State): void {
    if (last != State.None && last != State.Destroy) {
      // 前回は途中で切られた。ここで直す
    }
  }
  onPause(): void { }
  onDestroy(): void { }
}

const memo = new Memo();
register(memo);
```

- `App` は Réplique の基底クラスで、6 つのメソッドはどれも空。要るものだけ上書きする（案）
- `register(app)` をトップレベルで 1 回呼んで、OS にアプリを渡す（案）
- `State` は `None`（記録なし）・`Create`・`Start`・`Resume`・`Pause`・`Stop`・`Destroy`（案）
- AS では `() => {}` の中で `this` もローカル変数も使えない。ハンドラーからは、グローバルに置いたインスタンス（上の `memo`）を通す

いつ何を呼ぶか。Pause・Stop・Destroy に移るきっかけは決定、ほかは案です。

| できごと | 呼ぶもの |
| --- | --- |
| 起動 | `onCreate(最後の状態)` → `onStart` → `onResume` |
| 別のアプリなどにフォーカスが移った（戻る、別のアプリを開く、ページが隠れた） | その瞬間に `onPause`（決定）。プロセスにはイベントを届けない |
| Pause のまま、デバッグメニューで決めた時間が過ぎた | `onStop`（決定） |
| Pause の間に戻ってきた | `onResume` だけ |
| Stop のあとに戻ってきた | `onStart` → `onResume` |
| スタックから外れた・故意に破棄した | `onDestroy`（決定）。まだ Stop でなければ先に `onStop`（案）。返ったら Worker を止める |
| 例外・Worker の落ち・ページごと切られた | 何も呼ばない |

- Stop までの時間の既定値は未決
- ページが凍結されている間は時間を数えない。戻ってきてから時間を過ぎていれば、そのとき `onStop`（案）
- 「故意に破棄」は、OS の画面からアプリを閉じたとき（案）。アプリが自分を閉じる API は未決
- メソッドの中の例外は、ほかと同じくアプリの終了
- ホームと設定も `App` で書く

実装: まだ。今は `export function start()` だけ。

## 今はやらないこと

- 画面なしで動き続けるサービス。今のアプリはイベントが無いと動かず、タイマーも通信も無いため、出番がない
- 何段階もの重要度。見えている画面が 1 つなら、「前面」と「残している」で足りる
- 1 つのアプリが複数の画面を持つこと。`document` は画面ごとのものなので、あとで広げられる
- 開いていた画面やスクロール位置の復元
- 落ちたアプリの自動の再起動
