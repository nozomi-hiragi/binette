# アプリの識別子と提供リスト

[仕様の目次](README.md)

> [!NOTE]
> 2026-11-02 に決めた構成です。まだ実装していません。今のコードの形は [今のコードとの差](#今のコードとの差) にあります。見出しに **決定** と付いたものはのぞみが決めたこと、**案** と付いたものは提案です。

## 方針（決定 2026-11-02）

- アプリは **提供リスト** から入れる。提供者が自分の提供アプリの一覧（提供リスト）を公開し、ユーザーはその URL を登録する。登録したリストのアプリが、ストアのような所に並び、そこから入れる
- アプリの完全な ID は **提供リストの URL ＋ `#` ＋ アプリの識別子**。ID そのものが正しい URL になる
- 提供リストのページは HTML
- Cadre は独立したアプリで、提供リストから提供する。ホームと設定は Cadre のサブアプリとして、その中に置く
- アプリは **サブアプリ** を持てる。ID は親の識別子に `.` でサブアプリの識別子を連結したもの

## 完全な ID（決定 2026-11-02）

```
https://nozomi-hiragi.github.io/apps/#memo
└──────────── 提供リストの URL ──────────┘ └ アプリの識別子
```

- ID は URL として正しい形にする。開けば提供リストのページが返り、ブラウザは `id="memo"` の項目まで移動する
- フラグメント（`#` のあと）は「提供リストの中の、その識別子の項目」を指す。フラグメントはサーバーに送られないので、どの ID を開いてもリストのページそのものが返る
- 誰でも同じ識別子を名乗れるが、リストの URL が違えば別のアプリになる。同じ識別子のアプリでも、別のリストに載っていれば別のアプリとして扱う

### 細かい決まり（案）

- 読むときは `new URL()` を使い、正規化（ホストの小文字化、既定のポートの省略など）はブラウザの規則に任せる。比べるのは正規化したあとの文字列
- 提供リストの URL は `https:` に限る。クエリやフラグメントを持つリストの URL は誤り
- アプリの識別子に使える文字: 英小文字・数字・`-`、先頭は英字、1〜64 文字。URL エンコードなしでフラグメントに入る。`.` はサブアプリの区切りなので使えない
- 開発中（`http://localhost` など）の扱いは未決

## 提供リスト（決定 2026-11-02）

提供リストは HTML のページです。人がブラウザで開いて読め、OS は中の機械向けのリスト（JSON）を読みます。機械向けのリストの置き方は 2 つあり、どちらにも対応します。

1. `<link rel="binette-apps" href="apps.json">` で JSON を指す（PWA の `<link rel="manifest">` と同じ形）
2. HTML に埋め込む: `<script type="application/json" id="binette-apps">…</script>`。この種類の script は実行されない

OS はまず 1 の link を探し、無ければ 2 を読みます。

### 読み方の細かい決まり（案）

- 両方あれば link を使い、埋め込みは無視する
- link があって JSON が取れない・読めないときは、埋め込みに切り替えずに誤りにする（古い埋め込みが黙って使われないように）
- link の `href` は HTML の URL を基準に、JSON の中の相対 URL は JSON の URL を基準に解決する（埋め込みは HTML の URL を基準にする）
- どちらも無いページは「Binette の提供リストではありません」
- HTML は DOMParser で読むだけで、スクリプトは動かさない
- 別のオリジンから GET するので、提供リストの配信元が CORS を許す必要がある（GitHub Pages は許している）

### JSON の形（案）

```json
{
  "name": "のぞみのアプリ",
  "apps": [
    {
      "id": "memo",
      "source": "https://github.com/nozomi-hiragi/memo",
      "ref": "v1.2.0",
      "commit": "0123abcd...",
      "version": "1.2.0"
    }
  ]
}
```

- アプリの本体（`app.json` とソース）は、リストとは別の場所（GitHub のリポジトリなど）に置ける
- `app.json` の `id` がリストの `id` と一致しなければ、インストールで止める
- 更新は同じリストからだけ届く。リストが commit を固定するので、提供者がリストを書き換えたときだけ更新が届く
- HTML の各アプリの項目に `id="<識別子>"` を付けると、ID を開いたときにその項目まで移動する（付けるかは提供者の自由）

## Cadre・ホーム・設定（決定 2026-11-02）

- Cadre は独立したアプリ。提供リストから提供する
- ユーザー向けの呼び名は「枠アプリ」（英語 frame app）（決定 2026-11-02）。役割名 `cadre` は変えない
- ホームと設定は Cadre のサブアプリとして、Cadre の中に置く（例 `…#cadre.home`・`…#cadre.settings`）
- ホームは差し替えられる（[roles.md](roles.md)）。ほかの提供者が、ホームだけのアプリや、別の Cadre を配ってもよい
- Cadre を差し替えても、設定アプリの割り当ては変わらない（決定 2026-11-02）。役割の割り当ては役割ごとに独立していて（`system/boot.json` の既定と設定の `roles`、[roles.md](roles.md)）、`cadre` を変えても `settings` は既定の Cadre のサブアプリのまま。11/1 の決定「設定アプリはコアで差し替えられない」はそのまま
- 未決（案）: 既定の Cadre は、提供リストの ID のまま OS に同梱してプリインストールし、更新だけリストから受け取る。初回の起動がオフラインでも動き、復旧画面からも戻せる
- 未決（案）: OS に埋め込む、生の識別子（`:` を含まない、例 `settings`）の ID を残すか。残すなら、URL の ID は必ずスキーム（`https:`）を含むので衝突しない

## サブアプリ（決定 2026-11-02）

サブアプリは、親のアプリに完全に埋め込まれた、ユーザー側への「口」です（Android で 1 つのアプリがランチャーに複数の入口を出すのに近い）。

- ID は親の識別子 ＋ `.` ＋ サブアプリの識別子。例 `https://nozomi-hiragi.github.io/apps/#memo.widget`
- 親の `app.json` にサブアプリの ID を並べる。ファイルをどう分けるかは作者が決める
- 親と一緒にインストール・更新・削除される。単独では入れられない

### 細かい決まり（案）

- 深さは 1 段だけ。サブアプリの識別子の文字は、アプリの識別子と同じ
- 保存領域と権限は親と共有する。サブアプリが自分で持つのは名前・アイコン・役割だけ
- 入口は親の `entry.as` 1 つ。OS は起動のときに、どのサブアプリとして開いたかをアプリに渡し、アプリが中で振り分ける（クラスを分けるか、ファイルを分けて import するかは作者次第）
- 親と同時に動くときは、別の Worker、スタックの別の項目にする
- ホームの一覧に並べるのは画面を持つサブアプリだけにし、役割だけのものは並べない

`app.json` の書き方（案）:

```json
{
  "id": "cadre",
  "name": "Cadre",
  "roles": ["cadre"],
  "entry": { "as": "src/main.ts" },
  "sub": {
    "home": { "name": "ホーム", "icon": "home.svg", "roles": ["home"] },
    "settings": { "name": "設定", "icon": "settings.svg", "roles": ["settings"] }
  }
}
```

## 未決のこと

- 提供リストを引っ越したとき（リポジトリ名を変えたなど）。古いリストに移転先を書けるようにするか、別のアプリとして入れ直すか
- 最初から登録しておく提供リスト（のぞみのリストを既定にするか、空にするか）
- 開発中のアプリ（`localhost`）の扱い。リストを通さずライブモードで開くだけにするか
- 提供リストにハッシュを書いて改ざんを検出するか
- 画面の表示と App URL（`/<ID>`）に、短い形（`io.github.nozomi-hiragi/apps#memo` など）を使うか
- 今の同梱アプリ（`bundled/`、入手元 `binette:bundled`）をどう移すか

## 今のコードとの差

今のコードは次のままです。

- `app.json` の `id` は作者が書く自由な文字列（例 `io.github.nozomi-hiragi.binette.home`）。逆ドメインの部分は自己申告で、配信元とは関係がない
- Régie はアプリを `installedAppKey(source, id)`（`JSON.stringify([source, id])`）で区別する（[regie/store.md](regie/store.md)）。役割の割り当てや起動の履歴もこのキーを使う
- 入手元はシステムアプリが `binette:system`、同梱アプリが `binette:bundled`（[apps/](apps/README.md)）。ホームと Cadre もシステムアプリとして同梱している
- 提供リストとサブアプリは無い
