## 方針

- アプリ間で物を渡す「伝書鳩」の仕組み（Pigeon）を作る
- 通知の仕組みと兼ねる。宛先をユーザーにすれば通知になり、アプリにすればそのアプリの受信欄に入る
- 通知への返事をどう見せるか（ユーザーに出すか）はアプリ側のデザイン次第。通知の UI に入力欄を置き、ユーザーの返事を受け取る作りもあり得るので、それはそれで持てるようにする

## 形


OS が仲立ちする手紙です。似た仕組みは Android の Intent です。

```ts
const pigeon = api.get<PigeonApi>("pigeon");
pigeon.send("user", "chat.message", "題", "本文");        // 通知
pigeon.send("<アプリの ID>", "open", "", json);            // 受信欄へ
override onPigeon(): void { /* 受信欄が増えた */ }
```


- **手紙の形**：`{ from, to, kind, title, body, urgent?, actions? }`。宛先 `to` は `user` かアプリの ID。差出人 `from` は OS が付けるので偽れない。本文は文字列（JSON など）
- **宛先がユーザー（通知）**：Cadre が通知として出す（今の `cadre` API の通知の入口をこれにつなぐ）。ボタンや入力欄（`actions`）を付けてもよい。ユーザーが押したり入力したりした結果は、手紙として差出人の受信欄に入るだけで、OS はユーザーに何も出さない。付けなければ、通知を押すと差出人のアプリを開く。アプリごとに設定で通知を止められる。ユーザーに送るには `permissions` に `notify` が要る
- **宛先がアプリ（受信欄）**：手紙は受信欄（IndexedDB）に入る。起動時に受信欄を写して `pigeon.count()`・`pigeon.kind(i)` などで同期で読み、動いている間に届いたら `onPigeon()` が来る。読んだら `pigeon.done(i)` で消す。`urgent` なら OS が宛先を起動して渡す。受信欄の上限は 100 通（値は実装で見直してよい）
- **宛先を種類で選ぶ**：`app.json` に受け取れる種類（例 `"pigeon": ["open-image"]`）を書き、OS が候補を出してユーザーが選ぶ形（「このアプリで開く」）。後から足す
