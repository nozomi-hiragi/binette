# スケジューラ（定期実行）

[仕様の目次](README.md)

> [!NOTE]
> 2026-11-09 にのぞみが決めた構成です（この節の中身はすべて決定）。Régie のスケジューラ（TS）と OS の 3 つの予定を実装済みです。設定アプリの節とアプリの予定はまだです。

OS とアプリの定期実行を、Régie の 1 か所でまとめて持ちます。OS の更新確認、カタログ（提供リスト）の更新確認、アプリからのポーリングなど、定期的に動くものはすべてここに予定として登録し、設定アプリで一覧して変えられるようにします。

## 方針

- 定期実行はすべてスケジューラに登録する。ばらばらのタイマーは持たない
- スケジューラ（すべての予定の一覧と操作）は、設定アプリからだけ見て触れる
- アプリには、自分の予定を扱う API を渡す。初期値はアプリが API で送る。アプリの中で予定を見せるか・変えさせるかは、アプリの実装次第
- 実行できるとき（OS のページが開いているとき）にだけ動かす。動けない間のことは気にしない
- 閉じている間も確実に回したいものは、将来 Coulisses に頼む（今はやらない）

## 予定

| 欄 | 中身 |
| --- | --- |
| `id` | OS の予定は `os/<名前>`。アプリの予定は完全なアプリ ID と枠番号の組 |
| `owner` | `os` か、完全なアプリ ID。サブアプリは親とは別のアプリとして数える |
| `label` | 設定で見たときに分かりやすくするための表示名。任意 |
| `rule` | いつ実行するか（下の「予定の形」） |
| `enabled` | 止めているか |
| `last` | 前回の実行の時刻と結果（`ok` か `error: …`） |
| `registered` | 登録した時刻 |

- 設定の一覧に出す名前は、アプリの予定なら「アプリの名前＋ラベル」。ラベルが無ければ「スケジュール{枠番号+1}」（枠 0 なら「スケジュール1」）
- 保存するのは上の欄だけ。「次の実行」は保存せず、`rule` と `last` から出す

## 予定の形

決まった形の JSON だけを受けます。cron の書式は受けません。

```ts
{ "every": 1800 }                                       // 間隔（秒）
{ "at": "2026-11-10T09:00" }                            // 日時の指定（1 回だけ）
{ "daily": "07:30" }                                    // 毎日その時刻
{ "weekly": { "days": ["mon", "thu"], "time": "07:30" } } // 曜日と時刻
{ "monthly": { "day": 1, "time": "00:00" } }            // 毎月その日
```

- 時刻は端末の時刻帯（ローカル時刻）で解く
- 曜日は `mon`・`tue`・`wed`・`thu`・`fri`・`sat`・`sun`
- `monthly` で、その月に無い日（31 日など）は月末にする
- `every` の下限は、アプリの予定は 900 秒（15 分）、OS の予定は 60 秒（1 分）。下回る値は登録・変更を断る
- `at` は実行したら `enabled` を false にする。予定は残る

## いつ実行するか

- 「前回の実行のあとで、最初に来る予定の時刻」を過ぎていたら実行し、前回の実行の時刻を更新する。`every` なら前回＋間隔になる
- 一度も実行していないときは、登録した時刻を前回とみなす。登録してすぐには走らない
- 閉じていた間に何回分も過ぎていても、実行は 1 回だけ
- スケジューラは起動時と、ページが開いている間に確かめる
- 実行は 1 つずつ順番に行う
- 止めている予定（`enabled` が false）は実行しない

## OS の予定

| `id` | 表示名 | 初期値 | 中身 |
| --- | --- | --- | --- |
| `os/update` | OS の更新確認 | `{ "every": 1800 }` | ソフトウェア・アップデートの確認（今の `updater.check()`） |
| `os/catalogs` | カタログの更新確認 | `{ "every": 1800 }` | 登録したすべてのカタログを取り直し、更新を入れる（今の `system.lists` の確認）。カタログごとには分けない |
| `os/gc` | ストレージの片付け | `{ "every": 86400 }` | 参照されないファイルを消す（[storage.md](storage.md)） |

- 今ある 3 つの `setInterval` をやめ、この予定に載せ替える
- `os/catalogs` の初期値（30 分）は、アプリ管理の仕様が決める値（[app-manager.md](app-manager.md)）
- アプリ管理の「今すぐ確認」は、`os/catalogs` を今すぐ実行することにあたる。更新を自動で入れるかどうかはアプリ管理の決まりで、スケジューラは「いつ確認するか」だけを受け持つ

## アプリの予定

### 件数

- 予定は枠番号（0 から）で指す。今の上限は、アプリごとに 1 件（枠 0 だけ）。上限を増やしても API は変わらない
- 枠の外の番号を渡したら、操作は何もせず false を返す
- 使うには、`app.json` の `permissions` に `schedule` を書く。書いていないアプリには、辞書の `schedule` が届かない

### 登録と変更

- 登録（`register`）は、その枠に予定が無いときだけ登録する。すでにあれば何もせず false を返す。起動のたびに呼んでも、ユーザーが変えた値は消えない
- 変更（`update`）は、その枠に予定があるときだけ変える。無ければ false を返す
- ユーザー（設定アプリ）とアプリの変更がぶつかったら、あとに保存した方が勝つ
- アプリを削除したら、そのアプリの予定も消す

### 実行のしかた

- アプリのインスタンスが無ければ、OS がアプリを画面なしで起こし、`onSchedule(slot, api)` を呼ぶ（[lifecycle.md の「画面なしの起動」](lifecycle.md#画面なしの起動決定-2026-11-09)）
- インスタンスがあれば（どの状態でも）、そのインスタンスの `onSchedule(slot, api)` を呼ぶ
- 1 回の実行は `onSchedule` の呼び出し 1 回。上限は 30 秒で、過ぎたら止め、結果は `error: 時間切れ`。返ったら `ok`
- アプリは `onSchedule` の中で、自分の API（サーバーとの通信、Pigeon など）を使ってよい。新着があればユーザーに知らせる、などはアプリの仕事

## 設定アプリ

設定アプリに「定期実行」の節を置き、OS とすべてのアプリの予定を並べます。

- 一覧: 表示名、持ち主、予定の形、次の実行、前回の実行の時刻と結果
- 操作: 予定の形を変える、止める・再開する、今すぐ実行する
- アプリ管理の画面には出さない

## API

### TS（Régie）

```ts
system.scheduler.register({ id, owner, label, rule, run }); // OS の予定
system.scheduler.list();
system.scheduler.update(id, { rule?, enabled? });
system.scheduler.runNow(id);
system.scheduler.subscribe(listener); // 予定が変わったら知らせる
```

### AS（設定アプリ向け、キー `scheduler`）

役割 `settings` に割り当てられたアプリにだけ届きます。一覧は番号で数え、操作は `id` で指します（実行や保存の途中で一覧が変わっても、別の予定を操作しないため）。

```ts
const s = api.get<SchedulerApi>("scheduler");
s.count(); s.id(i); s.owner(i); s.label(i); s.rule(i); s.enabled(i);
s.next(i); s.lastTime(i); s.lastResult(i);
s.update(id, rule); s.setEnabled(id, on); s.runNow(id);
```

### AS（アプリ向け、キー `schedule`）

`permissions` に `schedule` を書いたアプリに届きます。自分の予定だけを扱えます。

```ts
const s = api.get<ScheduleApi>("schedule");
s.register(0, '{"every":1800}', "新着の確認"); // 登録。ラベルは任意
s.update(0, '{"daily":"07:30"}');             // 変更
s.remove(0);
s.exists(0); s.rule(0); s.enabled(0); s.lastTime(0); s.lastResult(0);
s.runNow(0);
```

```ts
class Mail extends App {
  onSchedule(slot: i32, api: Api): void { /* 新着を確かめる */ }
}
```
